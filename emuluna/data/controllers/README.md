# Controller illustrations

The active imported artwork is by **Pinapple_Graphics**, supplied in
`Controller_Vectors_by_Pinapple_Graphics_(Normal_300ppi)_v2.1`. It is converted
in reviewed batches using `tools/import_controller_art.py --only nes` (or other
registered diagram keys). Originals are untouched; derivatives fit within
1100 × 1100 px, preserve transparency, and use lossless WebP. Pillow is needed
only for conversion. The application uses Qt's WebP decoder and a bounded cache.

`artwork_manifest.json` records artist, source filename/hash, original and
exported dimensions, file sizes and processing. No license was supplied with
the folder; these images are not covered by EmuLuna's MIT license.
Existing NES/SNES app copies have local branding-removal edits, preserved in
this update and recorded separately in the manifest. Conversion skips locally
edited images unless `--replace-local-edits` is explicitly supplied.

The fallback SVGs are original EmuLuna illustrations generated by
`tools/generate_controller_art.py`. Existing console icons have separate
attribution. No OpenEmu controller artwork or implementation is used here.

To regenerate just one illustration without overwriting edits to other assets,
run `python3 tools/generate_controller_art.py --only snes` (or another diagram key).

`layouts.json` contains the fallback artwork's dimensions and interactive areas.
`imported_layouts.json` overrides the converted controllers with their own dimensions,
image paths and freshly aligned click targets. Regenerating fallback SVGs does
not overwrite these overrides. Controls on the back of a controller remain
available in the binding list even when they are not visible in the artwork.
The frontend draws both artwork and highlights with the same uniform transform.
The diagram key in `controller_profiles.json` associates a system with a layout;
systems sharing a physical controller can share an illustration.

Illustrations represent common hardware variants (US SNES, six-button Mega Drive,
DualShock, original Game Boy). They are simplified illustrations, not photographs.
Keypads whose cores use an on-screen selector are pictured even where individual
keys cannot be mapped directly. Those keys have no clickable binding hotspot.
Emulation input still depends on the core's chosen controller mode.

## Completed imported artwork

All 24 matching images now serve 27 catalog systems. Model choices include the
US SNES, six-button Genesis pad, black Saturn pad, original PlayStation
DualShock, TurboGrafx-16 TurboPad, indigo Game Boy Advance, purple Game Boy Color,
DS Lite, Atari 7800 CX78 gamepad and blue-violet SwanCrystal. Sega CD/32X share
the Genesis pad; PC Engine CD shares the TurboPad. No artwork was added for
consoles not supported by the app.

The original illustrations remain for Atari 5200, Odyssey², SG-1000, monochrome
Neo Geo Pocket and monochrome WonderSwan. These exact models are absent from the
provided set. `FALLBACKS` in the conversion tool records this explicitly.

Rear controls not visible in a supplied image stay in the binding list. The
data-driven `extra_groups` entries keep hidden shoulders/triggers grouped correctly.
The two-button TurboPad has six-button extensions in their own list group. Both
Lynx A/B pairs map identically; the Coleco keypad includes its supported axis-backed
9/0 controls; analog stick regions are separate from L3/R3 center clicks. The
Intellivision only exposes the direct keypad bindings supported by its profile;
the other numbers continue to use the core's on-screen keypad.
