# Software playback baseline — November 1, 2026

These are short diagnostic runs on the development machine, using original CC0
cartridges generated by the existing test helpers, the release Rust player,
SDL's OpenGL renderer and PipeWire audio. They do not benchmark commercial games
or establish hardware-rendered core/filter performance. The output was muted,
with real callback delivery checked by counters, rather than audible listening.

| Diagnostic / core | Normal displayed / executed | Forced 500 ms UI stall: displayed / dropped | Accepted and played stereo frames, each 300-frame run |
| --- | --- | --- | --- |
| NTSC NES / Nestopia | 300 / 300 | 271 / 29 | 239,541 |
| PAL SNES / Snes9x | 300 / 300 | 275 / 25 | 287,690 |
| Game Boy / Gambatte | 300 / 300 | 271 / 29 | 241,105 |

All six 300-frame runs reported zero playback missing, overflow and unplayed
frames. Each core also passed a one-frame start/drain/close check with every
accepted sample played. Tail callback silence (47–331 frames in these runs) is
reported separately; it is not counted as starvation during active playback.

The headless 180-frame checks reported no pixel/audio capacity growth after ten
warmup frames. Mean core execution plus owned snapshot time was approximately
1.107 ms (Nestopia), 0.487 ms (PAL Snes9x), and 0.150 ms (Gambatte). These values
include core-specific default options and are not comparable game workloads.

Instrumentation added before the Gambatte run measured 0.145 ms mean core plus
snapshot, 0.025 ms mean upload call and 0.091 ms mean draw/present call in its
normal session. Those are CPU call durations, **not GPU execution timestamps**.
The same session spent 144.636 ms waiting for audio queue space in total; the
ring preserved samples during device startup instead of discarding them.

Reproduce with `tools/check_playback.py`, supplying the installed compatible
core with `--core` and selecting `--diagnostic nes`, `snes-pal` or `gb`. Saves,
ROM and BIOS folders are temporary; the existing library is not used.

Six unit tests pass. The remaining work includes hardware GL/Vulkan ownership,
GPU filters, sustained clock-drift validation, egui controls, device routing,
full compatibility and application/package integration. A short stable software
run is not evidence that those tasks are complete.

## Direct Rust OpenGL presenter

The next stage replaced SDL Canvas presentation with an owned OpenGL context,
cached shader program, reusable source texture and a GPU filter draw directly
to the window. SDL still owns the native window/audio interfaces. The existing
Python application is not changed by this prototype.

The explicit live GPU test passed on AMD Radeon RX 9060 XT / Mesa 26.2.5,
OpenGL 4.6 core. It validates colors/orientation, black borders, interpolation,
scanline modulation, window resize/fullscreen and source size changes. Readback
is confined to the test; playback does not call `read_pixels`.

With the scanline shader enabled, the 300-frame Nestopia run displayed all 300
frames and played all 239,541 stereo sample frames. The 500 ms window stall run
displayed 271 / dropped 29, with all audio played. Both reported zero playback
missing/overflow/pending samples. Mean CPU upload/present calls were roughly
0.071 / 0.118 ms in the normal run. These are not GPU execution times, and the
simple shader is not equivalent to the user's complete CRT preset chain.

Seven ordinary unit tests and the explicit desktop GPU test pass. Hardware
libretro contexts, shared textures/fences and Vulkan images are still pending;
software pixels still cross one owned CPU snapshot and one GPU upload.

the following work supersedes them. The existing application is still separate.

The native shared-context tests verify leased textures under a forced consumer

three-frame changing-image comparison against the existing Qt GL renderer

peak 1.491 ms, with at most 16 game cards drawn per update. Artwork cache pixel

## Hands-on test build and native controls — November 2

The native library can now launch its sibling native player. Explicit short
end-to-end launch checks use the installed Wizards & Warriors / Nestopia and
Crazy Taxi / Flycast records. Library data remains immutable/read-only; installed
core checksums are validated off the interface thread, BIOS/NVRAM files are
copied into a bounded private folder and every session gets fresh temporary
saves. No existing game save directory is passed to a test player. Interactive
sessions end when closed, rather than at a developer frame limit. Theme files
load at runtime in both windows, including a Reload theme action in the browser.

Saved input handoff applies the existing legacy special-button migration in
memory without writing migration flags. Installed build IDs remain separate
from catalog IDs. Validated runtime/accessory choices are preserved; malformed
choices keep catalog defaults. Native controller event caching avoids repeated
per-snapshot SDL button/axis polling. Audio uses contiguous chunk publication and
consumption; callback end-of-session silence has independent accounting from
actual starvation, including cancellation and intentional discarded samples.

The egui gameplay controls use the worker command channel for pause, reset,
quick save/load and volume. UI-only redraw samples the completed image without
pixel upload or re-running a shader chain. Shared GL retains that source's lease
until replaced or closed, fencing every display read before returning the slot.
All 23 presets reproduced identical pixels across repeated UI-only redraws.
The expanded reset check allows a one-level 8-bit rounding difference: CRT Geom
Deluxe differed in 829 channels by at most 1/255 after extra display redraws;
other tested reset outputs remained identical. Do not call all reset output
bit-identical. Three themed pause buttons were clicked through real egui input;
paused filter changes keep controls drawable. Shared-GL tests also exercise
closing an interactive session while paused.

A real launch setting exposed a previously over-strict check: this installed
Flycast build leaves a GL_INVALID_OPERATION diagnostic from glBindTexture during
startup when the accurate-transparency option is selected. The test player had
aborted on any pending core GL error. It now drains, counts and rate-limits core
diagnostics separately from frontend operations. Context loss/out-of-memory and
all frontend allocation/FBO/snapshot errors still fail. An original fixture
injects an internal capability-probe error while providing known valid frame
colors, duplicates and a software fallback, verifying that usable frames survive
and the diagnostic remains counted. This does not prove arbitrary core errors
are harmless or fix the upstream texture diagnostic.

Latest Crazy Taxi check: installed Flycast, accurate transparency selected,
1920x1440 internal setting, CRT Geom Deluxe, native controls, 2560x1440 fullscreen,
copied system files and temporary saves. A scripted Start at frame 600 dismissed
the memory-card prompt; the final capture shows a real 3D attract scene. All
1,800 submitted frames displayed, zero dropped frames, zero missing/overflow/
pending audio, 1,797,020 stereo frames accepted and played, 100 tail-silence frames,
zero CPU video bytes and one counted core GL diagnostic. Core work totaled
9,181.512 ms (startup peak 71.915 ms); GPU snapshot calls totaled 66.569 ms. Two
earlier checks stopped at the memory-card prompt and are not dynamic-scene
performance evidence. No sustained driving or matched RetroArch claim is made.

A prior Panzer Dragoon run reached Episode 1 combat, verified by captures showing
HUD, reticle, enemies and health, rather than a title/intro. Full CRT fullscreen:
4,800 displayed, zero dropped/missing/overflow/pending, 3,852,162 stereo frames
accepted/played and 126 tail-silence frames. Mean core/snapshot 6.171 ms, peak
14.288 ms; mean upload 0.051 ms and presentation call 0.159 ms. Diagnostic captures
were made every 300 frames in that run. These were warm/repeated ROM tests:
omitting --content-digest with a core launch profile hashes the entire ROM before
playback and warms its file cache. The library handoff supplies the stored game
ID. None of these results establish cold disc-I/O behavior, compositor scanout,
GPU execution timings or audible waveform quality (device tests were muted).

The ordinary workspace suite currently contains 50 passing tests. The strict
workspace Clippy check passed before the final diagnostic-fixture expansion;
repeat checks after subsequent changes. Existing save-state envelopes also
passed Python-to-Rust and Rust-to-Python checks for all three renderer tags;
Vulkan tagging compatibility does not mean native Vulkan playback is implemented.

### GL contract correction

The follow-up audit found that native transport texture/framebuffer/renderbuffer
bindings were left live across the core boundary, and the initial core target
was not explicitly cleared. Transport now cleans its bindings after allocations
and copies; the initial target clears color, depth and stencil independently of
incoming scissor/write masks. A new core-side binding assertion and a full-target
black-pixel check passed with the existing fixture/restart/control/preset tests:
nine explicit live GPU checks passed. See `LIBRETRO_CONFORMANCE.md` for the audit,
remaining limitations and the carefully limited RetroArch diagnostic comparison.

### Lifecycle and performance-interface expansion

The reproducible contract script now compiles original fixtures in a temporary
folder and runs three native bridge tests plus ten live GPU/audio tests. It
requires no installed game/library or BIOS. Coverage includes all software pixel
formats with padded rows, stable content pointers, variable defaults, geometry
and timing changes, stereo output, normal shutdown and explicit reset. CPU
feature flags are encoded by the fixture and independently checked against Rust
runtime feature detection. Timing counters remain monotonic, duplicate counter
registration preserves totals, and the shared bridge exposes all performance
interface function pointers. Four existing Python/native audio-clock tests also
passed after the interface addition. No SIMD-related speedup is claimed.

The expanded control fixture injects GL diagnostics in context reset, frame
execution, state save, reset and state load. All seven were counted in the
120-frame session, which displayed every frame with zero missing/overflow/pending
audio. Total accepted 96,152 = 92,106 played + 4,046 intentionally discarded; 54
tail-silence frames were separate. The paused interactive-close test counted two
injected diagnostics and exited normally. A separate five-frame GL session
verified that RETRO_ENVIRONMENT_SHUTDOWN is a normal end, not a frame failure.

A synchronous debug call stack places the remaining native Flycast invalid-
texture call inside glsm_ctl → retro_run → el_frame on frame zero. That establishes
the call site, rather than merely guessing from the final error flag. It does not
yet establish why the core's texture-state cache contains that name or prove
that all core diagnostics are harmless.

### Audio callback chronology correction

A new original fixture submitted half a frame at 48 kHz and half at 24 kHz during
one retro_run. Before the fix, frame zero produced 1,200 stereo frames instead of
800. After recording rate-change boundaries, all six tested frames had exactly
800 samples at 60 Hz or 960 at 50 Hz, preserving each half's distinct stereo
values. Coverage includes both per-sample and batch callbacks. Four native bridge
contract tests and four existing Python/native audio-clock tests passed. Strict
workspace Clippy and the release build passed. No claim is made that this explains
the Sega CD movie stutter or every core's performance.
